# ThemePark — 테마파크 동선·혼잡 시뮬레이터 (처음부터 만드는 순서)

가상의 테마파크(써니힐스 파크)에 하루 수천 명의 방문객 NPC가 입장 → 이동 → 줄서기 → 탑승 → 식사·휴식·구경 → 퇴장을 반복합니다.
사용자가 지도에서 출발점(또는 방문객)을 고르고 놀이기구를 선택하면 **최단 거리 / 최소 시간 경로와 예상 이동·대기·총 소요시간**을 보여 주고,
모든 방문객의 이동 데이터를 모아 **관제 화면**(히트맵, 보행로 서비스 수준, 놀이기구별 이용량, 혼잡 지점, 이동거리 분포, 안내 정확도)에 표시합니다.
CleanerBot·WeldingBot과 같은 방식(Unity CLI + Pipeline 패키지, `tp_` 명령, 명령 하나로 씬 재생성)으로 만들었습니다.

- 환경: Windows, Unity 6000.6.3f1 (URP, `com.unity.template.urp-blank`), Unity CLI 1.0.0-beta.11
- 경로: `D:\UnityAIProjs\DigitalTwin\ThemePark`
- 패키지 추가: `com.unity.pipeline` 0.8.0-exp.1 (`[CliCommand]` → `unity command tp_*`)
- 작업 순서: C# 작성 → `AgentTools\dryrun.ps1` (컴파일 확인) → `Refresh.cs` → `tp_*` 명령 → `snap.ps1` 스크린샷 → git 커밋
- 처음 만들기: `unity projects create ThemePark --path D:\UnityAIProjs\DigitalTwin --editor-version 6000.6.3f1 --template com.unity.template.urp-blank --no-cloud`
  → manifest에 `com.unity.pipeline` 추가 → Editor 열기 → `tp_setup_scene`

## 3. 시뮬레이션 모델
- 도착: 75%는 정규분포(10:00, σ 0.8 h, 9~15시), 25%는 9~17시 균등. 체류 5.5 h(σ 1.5 h)
- 선택 효용: 2.2·인기 + 1.6·(1 − |스릴 − 취향|) − 0.10·이동(분) − 0.05·대기(분) − 1.4·탑승 횟수 (+ 가족은 키즈 +1.2, 키 제한 −2.5) + Gumbel 잡음
- 배고픔(점심 11:30~13:30 ×2.2)·피로(시간 + 이동거리) → 식당/휴식. 식당이 모두 25분 이상 대기면 식사를 미룸
- 결정마다 50% 확률로 40~240 s 거리의 교차로로 산책 → 4~18분 구경(상점·포토존 대신)
- 보행 속도: 1.3 m/s(σ 0.15, 유형별 보정) × Weidmann 계수(간선 밀도 = 걷는 사람 + 넘친 대기열 / 면적). 오른쪽 통행 경향
- 경로: 안내 앱 사용자(기본 50%)는 현재 밀도로 계산한 최소 시간 경로와 예측 대기, 나머지는 최단 거리와 현재 대기로 판단
- 대기 예측: 현재 대기 = 다음 배차까지 + ⌊앞사람/정원⌋ × 간격. 예측 대기 = 도착 시점 대기열(최근 유입률 − 처리율) 기준
- 대기열: 지그재그 대기 구역(10 m × 깊이) → 넘치면 정문 방향 보행로 한쪽에 두 줄로 서며, 그만큼 보행로 밀도에 더해짐

## 4. CLI 명령 (`AgentTools\tp.ps1 <명령>`)
- 장면: `tp_setup_scene [--visitors]`, `tp_setup_font`
- 분석(씬 변경 없음): `tp_park_info`(레이아웃·겹침 검사), `tp_sim_run [--visitors --seed --guided --until --export]`(하루 실행 + 검증), `tp_sim_compare --guided 0,0.5,1`, `tp_route --to <이름> [--from x,z|gate] [--at HH:MM]`
- 에디트/플레이: `tp_preview --at 12:00`(그 시각까지 계산해 화면에 표시), `tp_view guest|control`, `tp_camera`, `tp_display --color --heat --edges`, `tp_guide --to <이름> --from gate|x,z|visitor:<id>|random`, `tp_sim_advance`, `tp_sim_status`, `tp_export`
- 플레이 모드: `tp_sim_start --speed`, `tp_sim_pause`, `tp_sim_reset [--visitors --guided]`, `tp_sim_speed`
- 도구: `snap.ps1 <이름> [w] [h] [camera|screen]`, `focus_unity.ps1`, `dryrun.ps1`, `hashes.ps1`, `SetLang.cs`, `ScrollDash.cs`(대시보드 스크롤), `CheckScene.cs`(스크립트 누락 확인)

## 6. 알려진 한계
- 방문객은 개인 단위(가족 묶음 이동 없음), 화장실·공연 일정·패스트패스는 없음. 구경은 교차로 옆에 머무는 것으로 단순화
- 보행 충돌 회피는 하지 않고 밀도로 속도만 줄임. 대기열 넘침은 정문 방향 한 경로만 사용
- 안내 앱의 효과가 작게 나옴: 대기 분산(덜 붐비는 놀이기구 추천)이나 가상 대기열은 아직 없음
- 플레이 모드 중 스크립트를 고치면 다시 컴파일되면서 시뮬레이션이 처음부터 시작됨
